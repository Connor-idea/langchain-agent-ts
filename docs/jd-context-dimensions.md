# JD 生成的上下文维度评估框架

## 核心问题

> 生成一份好 JD，到底需要知道什么？

答案：**三个圈的交集**。

```
        ┌─────────────┐
        │  业务需要什么  │
        │  (战略/目标)   │
        └──────┬───────┘
               │
    ┌──────────┼──────────┐
    │          │          │
    ▼          ▼          ▼
┌───────┐ ┌───────┐ ┌───────┐
│团队缺什么│ │市场有什么│ │预算能买什么│
│(组织)  │ │(供给)  │ │(约束)  │
└───────┘ └───────┘ └───────┘
```

JD = 业务需要 ∩ 团队缺的 ∩ 市场能提供的 ∩ 预算买得起的

**缺任何一个维度，JD 就会有问题：**
- 不知道业务需要 → 招来的人不解决实际问题
- 不知道团队缺什么 → 招来的人和现有团队重叠或冲突
- 不知道市场供给 → 写了一堆要求但招不到人
- 不知道预算约束 → 要求 100 分的能力，只给 60 分的钱

## 一、业务维度（Business Context）

> "为什么要招这个人？"

| 维度 | 问题 | 影响 JD 的哪个部分 |
|------|------|-------------------|
| **战略方向** | 公司未来 1-3 年往哪走？ | 岗位定位、成长路径 |
| **业务阶段** | 初创/成长/成熟/转型？ | 职责重心（0→1 vs 1→N） |
| **业务目标** | 未来 12 个月要达成什么？ | 可衡量的产出指标 |
| **老板期望** | 老板对这个岗位的真实期望？ | 隐性要求、优先级 |
| **业务痛点** | 当前最大的业务瓶颈是什么？ | 核心职责定义 |

**缺失后果：** 招了一个"标准前端"，但业务需要的是能做数据大屏的可视化专家。

### 评估方法

```
输入完整性评分：
□ 有明确的业务目标描述          (+2)
□ 有老板/高管对岗位的期望       (+2)
□ 有业务痛点分析               (+2)
□ 有未来 12 个月的里程碑        (+1)
□ 有业务阶段判断               (+1)
满分: 8 分
```

## 二、组织维度（Organizational Context）

> "这个人进来后，在哪里、和谁、怎么工作？"

| 维度 | 问题 | 影响 JD 的哪个部分 |
|------|------|-------------------|
| **团队结构** | 现在团队有哪些人？各什么水平？ | 职责分工、能力互补 |
| **技能缺口** | 团队最缺什么能力？ | 任职要求的优先级 |
| **管理风格** | 扁平/层级？自主性要求多高？ | 软性素质要求 |
| **协作模式** | 和谁协作？上下游是谁？ | 职责边界、沟通要求 |
| **团队文化** | 团队氛围是什么样的？ | 文化匹配要求 |
| **汇报关系** | 向谁汇报？有没有人向 TA 汇报？ | 职级定义 |
| **成长路径** | 这个人 1 年后、3 年后会怎样？ | 吸引力、稳定性 |

**缺失后果：** 招了一个需要明确指令的人，但团队是扁平管理、需要自驱力。

### 评估方法

```
输入完整性评分：
□ 有完整的团队成员列表（角色/级别/技能）  (+3)
□ 有明确的技能缺口分析                   (+2)
□ 有管理风格描述                         (+1)
□ 有协作关系说明                         (+1)
□ 有团队文化关键词                       (+1)
□ 有成长路径规划                         (+1)
□ 有汇报关系说明                         (+1)
满分: 10 分
```

## 三、岗位维度（Job Context）

> "这个人具体要做什么？"

| 维度 | 问题 | 影响 JD 的哪个部分 |
|------|------|-------------------|
| **核心职责** | 这个人来了之后，前 3 个月要做什么？ | 职责描述 |
| **成功标准** | 怎么衡量这个人干得好不好？ | 可衡量的产出指标 |
| **工作内容占比** | 70% 写代码 + 20% 沟通 + 10% 管理？ | 职责优先级 |
| **决策权限** | 能决定什么？不能决定什么？ | 职责描述、职级 |
| **一票否决** | 有什么情况绝对不能接受？ | 筛选标准 |
| **历史岗位** | 这个岗位之前有人吗？为什么离开？ | 避免重复踩坑 |

**缺失后果：** JD 写了 8 条职责，但实际工作 80% 是其中 2 条。

### 评估方法

```
输入完整性评分：
□ 有具体的前 3 个月任务描述              (+3)
□ 有成功标准/衡量指标                    (+3)
□ 有一票否决条件                         (+1)
□ 有决策权限说明                         (+1)
□ 有岗位历史（前任情况）                  (+1)
□ 有工作内容占比                         (+1)
满分: 10 分
```

## 四、市场维度（Market Context）

> "市场上这样的人多不多、贵不贵？"

| 维度 | 问题 | 影响 JD 的哪个部分 |
|------|------|-------------------|
| **人才供给** | 这类人才在市场上多不多？ | 要求的严格程度 |
| **薪酬行情** | 这个级别的市场薪酬是多少？ | 薪酬范围 |
| **竞品 JD** | 竞争对手怎么写 JD？ | 差异化卖点 |
| **热门技能** | 当前市场上最抢手的技能是什么？ | 技能要求优先级 |
| **流动率** | 这类岗位的平均在职时间是多少？ | 稳定性预期 |
| **招聘周期** | 这类岗位平均多久能招到？ | 紧急程度判断 |

**缺失后果：** 要求 5 年经验 + 全栈 + 会 AI，薪资 15K——市场上根本没人来。

### 评估方法

```
输入完整性评分：
□ 有市场薪酬数据（分位数）              (+3)
□ 有人才供给判断（紧缺/充足/过剩）       (+2)
□ 有竞品 JD 参考                        (+2)
□ 有招聘周期预估                         (+1)
□ 有热门技能趋势                         (+1)
满分: 9 分
```

## 五、候选人维度（Candidate Context）

> "什么样的人会被这份 JD 吸引？"

| 维度 | 问题 | 影响 JD 的哪个部分 |
|------|------|-------------------|
| **目标画像** | 理想候选人现在在哪里工作？ | 吸引力定位 |
| **求职动机** | 这类人为什么想换工作？ | JD 卖点 |
| **决策因素** | 这类人选择工作时最看重什么？ | 福利/文化/成长 |
| **信息渠道** | 这类人在哪里看 JD？ | 渠道策略 |
| **简历特征** | 这类人的简历长什么样？ | 筛选标准 |

**缺失后果：** JD 写得很好，但发布在错误的渠道，目标候选人根本看不到。

### 评估方法

```
输入完整性评分：
□ 有目标候选人画像                      (+2)
□ 有求职动机分析                        (+2)
□ 有决策因素排序（薪酬/成长/文化/...）    (+2)
□ 有渠道策略                            (+1)
满分: 7 分
```

## 六、约束维度（Constraint Context）

> "有什么限制条件？"

| 维度 | 问题 | 影响 JD 的哪个部分 |
|------|------|-------------------|
| **薪酬预算** | 最低/最高/理想？ | 薪酬范围 |
| **时间约束** | 多久必须到岗？ | 紧急程度 |
| **硬性门槛** | 学历/年龄/证书/背景？ | 任职要求 |
| **合规要求** | 有没有法律/政策限制？ | JD 措辞 |
| **地理约束** | 必须在某个城市？远程？ | 工作地点 |
| **HC 限制** | 只招 1 个还是可以多个？ | 招聘策略 |

**缺失后果：** JD 写了"薪资面议"，候选人以为没预算，直接跳过。

### 评估方法

```
输入完整性评分：
□ 有明确的薪酬范围                      (+3)
□ 有到岗时间要求                        (+1)
□ 有硬性门槛说明                        (+2)
□ 有工作地点/远程政策                    (+1)
□ 有 HC 数量说明                        (+1)
满分: 8 分
```

## 综合评估矩阵

| 维度 | 权重 | 满分 | 当前 JD 生成器覆盖 |
|------|------|------|-------------------|
| 业务维度 | 25% | 8 | ✅ bossExpectation, strategy, businessGoals |
| 组织维度 | 25% | 10 | ✅ DepartmentProfile, team, culture |
| 岗位维度 | 20% | 10 | ⚠️ rawNeed（口语化，不够结构化） |
| 市场维度 | 15% | 9 | ⚠️ 只有内置基准，无实时数据 |
| 候选人维度 | 10% | 7 | ❌ 未覆盖 |
| 约束维度 | 5% | 8 | ⚠️ 只有 budget，缺其他约束 |
| **总分** | 100% | **52** | **当前覆盖约 60%** |

## 当前缺失的维度

### 高优先级（直接影响 JD 质量）

1. **岗位维度 - 结构化需求**
   - 当前：只有 `rawNeed`（口语化描述）
   - 需要：前 3 个月任务、成功标准、工作占比、决策权限
   - 解决：需求访谈 Agent

2. **候选人维度 - 目标画像**
   - 当前：完全缺失
   - 需要：理想候选人画像、求职动机、决策因素
   - 解决：候选人画像生成

3. **市场维度 - 实时数据**
   - 当前：只有内置基准
   - 需要：实时薪酬、供给、竞品 JD
   - 解决：L2 搜索集成

### 中优先级（锦上添花）

4. **岗位维度 - 历史信息**
   - 前任为什么离开？做得好/不好的地方？
   - 解决：复盘 Agent

5. **组织维度 - 继任规划**
   - 这个岗位的人将来可能往哪走？
   - 解决：职业路径 Agent
